8. 缺陷汇总与复现

NEW 编号为本报告临时编号；新增严重度按测试计划规则初评，需开发负责人最终 triage。

编号严重度状态摘要影响
AJX-001高仍可复现已取消 signal 不传播，请求前取消仍发送阻断
AJX-002中仍可复现HTTP 失败未清理 timeout timer发布前修复
AJX-003中仍可复现无 Content-Length 泄漏原生 TypeError发布前修复
AJX-004中仍可复现Service 声明为 Promise<T>类型消费者受影响
NEW-001高（待 triage）新发现原生 ESM 入口不可加载阻断 ESM/Node
NEW-002高（待 triage）新发现PATCH alias 使用小写方法阻断 PATCH
NEW-003中（待 triage）新发现default export 文档与产物不一致API 契约混乱

AJX-001：请求前取消失效

{"aborted":false,"reason":null}
{"outcome":"fulfilled","fetchCalls":1,"result":{"sent":true}}

Chromium 也确认请求到达服务器。建议合并 signal 时先处理已 aborted 输入、保留 reason，并在进入 Fetch 前再次检查。修复后将两条 expected-fail 转为普通用例。

AJX-002：失败路径 timer 泄漏

{"outcome":"rejected","type":"networkError","isNetworkError":true,"activeTimers":1}

建议用覆盖 Fetch、status、进度和解析全过程的 finally 清理 timer。

AJX-003：无 Content-Length 泄漏 TypeError

{"constructor":"TypeError","message":"Cannot read properties of undefined (reading 'buffer')","isAjaxError":false}

建议回退到标准 response 解析，或把结果转换阶段纳入 AjaxError 包装。

AJX-004：Service 返回类型不一致

TS2322: Type 'Promise<User>' is not assignable to
type 'Promise<AjaxResponse<User>>'.

应统一声明、README 与运行时，并在修复后移除对应 @ts-expect-error。

NEW-001：原生 ESM 入口不可加载

真实 tarball 安装后执行原生 import 即报 ERR_MODULE_NOT_FOUND。建议生成显式 .js specifier，并用 .mjs、子目录 package.json 或明确构建布局区分 ESM/CJS；CI 增加 tarball 消费测试。

NEW-002：PATCH alias 使用小写方法

源码以 aliasWithBody('patch') 注册；Chromium 对严格 HTTP server 得到 400，而 method: 'PATCH' 对照成功。建议标准方法统一大写，并增加真实 HTTP server 集成用例。

NEW-003：default export 契约不一致

README 标为 default export，源码只有 export-star，CJS 没有 default，声明末尾为 export = Ajax。应选择“仅命名导出”或“同时支持 default”，同步所有层面并补测试。
